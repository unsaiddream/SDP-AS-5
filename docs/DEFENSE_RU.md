# Подготовка к защите

## Короткое объяснение проекта

«Моя программа выбирает маршрут по цели доставки. RoutePlanner — Context: он хранит RouteStrategy и делегирует ей выбор. Пять стратегий минимизируют время, стоимость, экологический балл, взвешенный набор критериев или расстояние. Сначала общая реализация исключает маршруты, нарушающие ограничения. StrategySelector выбирает алгоритм по запросу. В Main я три раза меняю стратегию одного объекта без перезапуска».

## Порядок демонстрации

1. Выполнить `mvn clean verify`, показать 38 успешных тестов.
2. Выполнить `mvn exec:java`, показать разных победителей B/D/C/G/E.
3. Открыть RoutePlanner: в plan есть только делегирование, формул нет.
4. Открыть RouteStrategy: объяснить, зачем RouteDecision лучше одного Route.
5. Открыть ScoredRouteStrategy: проверка входа → показатели → ограничения → ранжирование → объяснение.
6. Открыть BalancedRouteStrategy: объяснить min/max, нулевой вклад постоянного критерия и сумму весов.
7. Открыть StrategySelector: карта передаётся извне; ecoPreferred меняет только STANDARD.
8. Показать `git show 87dabaa --stat`: пятая стратегия и регистрация в Main, без изменений Context.

## Вопросы и ответы

**Почему нельзя просто выбрать min по времени?** Время меняется из-за пробок, а самый быстрый маршрут может быть недоступен или превышать бюджет. Сначала проверяю допустимость, затем сравниваю итоговое время.

**Почему стоимость рассчитывается вне Cheapest?** Её используют и ограничения, и Balanced, и вывод. Общая модель стоимости предотвращает расхождение: Cheapest отвечает за минимизацию этой величины.

**Что если допустимых маршрутов нет?** Выбрасываю NoSuitableRouteException с причинами. В сравнении ошибка становится отдельной записью для стратегии. Null не возвращается.

**Зачем нормализация?** Без неё стоимость в тысячах подавила бы CO2 в единицах. Min-max переводит критерии в диапазон 0..1; веса задают относительную важность.

**Что если все значения одинаковы?** Вклад критерия ноль: он не помогает отличить маршруты. При полном равенстве выбирается меньший id.

**Почему фильтрация идёт до нормализации?** Недопустимые маршруты не должны влиять ни на победителя напрямую, ни на масштаб критериев косвенно.

**Strategy или Template Method?** Между Planner и взаимозаменяемыми алгоритмами — Strategy. Внутри ScoredRouteStrategy общий процесс с переопределяемой оценкой — Template Method. Паттерны совместимы.

**Где runtime switching?** Main использует один planner: первоначально Fastest, затем три setStrategy для Cheapest, Eco и Balanced.

**StrategySelector тоже Strategy?** Нет: он выбирает объект алгоритма по бизнес-правилу; алгоритм выбирает маршрут по данным.

**Почему immutable records?** Они компактно описывают данные, дают value equality и не позволяют менять поля после создания. Вложенные коллекции дополнительно копируются, поскольку record сам по себе не делает их immutable.

**Как доказать OCP?** Пятая стратегия добавлена новым классом; существующий Context не изменён. Изменение Main нужно только для подключения в демонстрацию.

**Чем отличается от Bridge?** Strategy — смена алгоритма одной операции. Bridge — независимое развитие абстракции и её реализации, например уведомления и канала отправки.

## Пример live modification

Задание: создать стратегию минимальных выбросов без учёта расстояния.

1. Создать `MinimumEmissionStrategy extends ScoredRouteStrategy` в пакете delivery.strategy.
2. `getStrategyName()` возвращает название.
3. `formula()` возвращает `score = carbonEmission`.
4. `scoring(...)` возвращает `a -> a.route().carbonEmission()`.
5. Добавить объект в список сравнения Main. Planner менять не требуется.
6. Добавить тест с двумя маршрутами: дальний с меньшим CO2 должен победить ближний с большим CO2.
7. Выполнить `mvn test`, затем `mvn exec:java`.

Другая простая модификация: заменить веса Balanced на (1, 0, 0, 0). Для того же допустимого набора победитель должен совпасть с Fastest, поскольку нормализация сохраняет порядок времени.

## Чего не утверждать

Это выбор среди кандидатов, не Dijkstra и не полная оптимизация логистики. Коэффициенты демонстрационные. Тесты выполнялись на JDK 25 с target Java 17, а не непосредственно на JDK 17. Публикация GitHub и сдача Moodle не выполнены этим локальным запуском.
